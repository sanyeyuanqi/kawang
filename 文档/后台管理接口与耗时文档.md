# 后台管理页面接口与耗时文档

> Base URL: `/api/v1`
> 代码来源：`backend/app/api/v1/admin/*`、`backend/app/api/v1/auth.py`、`frontend/src/pages/admin/*`
> 更新日期：2026-06-08

## 1. 说明

后台管理页面实际调用两类接口：

1. 通用认证接口：登录页、自动刷新 token、读取当前用户、退出登录。
2. 后台管理接口：前缀 `/admin`，后端统一挂载为 `/api/v1/admin/*`。

除登录、刷新 token 外，后台管理接口都需要请求头：

```http
Authorization: Bearer {access_token}
```

通用成功响应：

```json
{
  "code": 200,
  "msg": "success",
  "data": {}
}
```

通用错误响应：

```json
{
  "code": 400,
  "msg": "错误原因",
  "data": null
}
```

## 2. 耗时采集口径

当前代码只在前台 `/orders/mine` 和通用认证依赖里有局部 timing 日志，后台管理接口没有逐接口阶段耗时日志。因此本文件中的“阶段耗时”写的是每个接口可拆分的执行阶段和当前采集状态；毫秒级实测值需要开启后台 timing 后再补。

建议统一阶段字段：

| 阶段字段 | 含义 | 当前状态 |
|---|---|---|
| `auth_decode_ms` | JWT 解码 | 通用认证依赖可记录，但目前只对 `/orders/mine` 打日志 |
| `auth_redis_ms` | Redis 校验 access token | 同上 |
| `admin_check_ms` | 管理员角色与账号状态校验，命中 15 秒内存缓存时接近 0 | 未单独打日志 |
| `cache_lookup_ms` | 接口本地/Redis 缓存读取 | 未单独打日志 |
| `db_query_ms` | 数据库查询 | 未单独打日志 |
| `db_write_ms` | 新增、更新、软删除、批量更新、`flush/refresh` | 未单独打日志 |
| `external_ms` | 支付退款、邮件、文件 IO 等外部操作 | 未单独打日志 |
| `cache_invalidate_ms` | 清理商品、分类、库存、公告、订单相关缓存 | 未单独打日志 |
| `serialize_ms` | 组装响应 JSON / CSV | 未单独打日志 |
| `total_ms` | 接口总耗时 | 本次实测见第 13 节；线上代码默认不输出后台 timing 日志 |

已知本地日志样本：`backend-timing-8001.err.log` 只有 `/api/v1/orders/mine` 的阶段耗时，例如 `jwt_decode=0.13ms`、`redis_token_get=38.95ms`、接口总耗时 `999.33ms`。没有后台接口实测阶段耗时，不能直接套用。
